# feat: Add Big Content Words rewards and Blue Fox Red Whale story mode

## Overview

Add a two-part narrative reward layer to the reading app: (1) Big Content Words earned after 61 designated lessons with celebratory reveals and a collection gallery, and (2) an illustrated 25-page story that unlocks when all words are collected. Includes image generation pipeline via Nano Banana 2 API.

## Problem Frame

Kids complete phonics lessons without building toward anything larger. This feature creates a compounding reward loop: lessons earn vocabulary words, words unlock a story, and the story provides visual reveals that incentivize reading further. (see origin: `docs/brainstorms/blue-fox-story-requirements.md`)

## Requirements Trace

- R1. Earn Big Content Words after 61 designated lessons
- R2. Full-screen celebration on first-time completion (tap to dismiss → next lesson)
- R3. Inline badge on revisit completion
- R4. 61 unique word images (Nano Banana 2, watercolor style)
- R5. Collection gallery at `/reading/collection`
- R6. Story unlocks when all 61 words collected (last = "gold" after lesson 100)
- R7. Invitation/unlock screen with "Start Reading" + persistent header icon access
- R8. 25 pages, 4 chapters per page, 100 chapters total
- R9. 25 four-panel illustrations (Nano Banana 2)
- R10. Side-by-side layout (desktop) / stacked (mobile)
- R11. Blur-to-sharp panel reveal on chapter text entry
- R12. Tap-to-advance default + word-tap toggle
- R13. Per-chapter story progress persistence, sequential nav only
- R14–R17. Image generation pipeline and prompt consistency
- R18. Header icons for collection and story access

## Scope Boundaries

- Word/story system covers lessons 1–100 only (101–175 intentionally excluded)
- Story is read-only — no quizzes or comprehension checks
- No audio or TTS
- Images are static assets generated once, not runtime
- Images stored in `public/`, lazy-loaded, WebP format

## Context & Research

### Relevant Code and Patterns

- `src/contexts/ReadingProgressContext.tsx` — Progress persistence via `useState(() => loadFromLocalStorage())` sync init pattern. Contains `completedLessons[]`, `wordCounts`, `lastVersions`. Extended in-place for new fields.
- `src/pages/reading/ReadingPage.tsx` — Single-route reading experience. Header has logo (top-left), hamburger (top-right), UserMenu (top-right at `right-16`). New icons go between logo and hamburger.
- `src/pages/reading/components/LessonDisplay.tsx` — Lesson completion state machine: `highlightIndex` advances → `lessonComplete = true` → `onComplete` fires → "Next Lesson" button appears. Celebration inserts between `onComplete` and the button.
- `src/data/reading/lessons.ts` — Generated by `scripts/convert-reading-csv.ts`. Contains `readingLessons[]`, `getLesson()`, `getWordTokens()`, `selectVersion()`.
- `scripts/convert-reading-csv.ts` — CSV-to-TypeScript generator with custom parser, verification, and function generation.
- `src/lib/userStorage.ts` — `SCOPED_BASE_KEYS` array used by `removeAllUserKeys()` for cleanup on reset/delete.
- `src/App.tsx` — React Router v7 with `BrowserRouter basename="/grade-nerd"`. Flat route structure for reading (`/reading`).
- `public/images/` — Static image assets referenced as `/grade-nerd/images/...`. No lazy loading currently.

### Institutional Learnings

- **CRITICAL: Save-on-mount race condition** (`docs/solutions/logic-errors/save-on-mount-race-condition-async-init-overwrites-data-2026-04-17.md`) — Never use `useEffect` for localStorage loads. Always use `useState(() => loadFromLocalStorage())` sync initializer. ReadingProgressContext already follows this pattern; new fields must preserve it.
- **State invariant completeness** (`docs/solutions/ui-bugs/react-state-version-lock-lesson-picker-reading.md`) — Every setter that touches related state fields must maintain all invariants. When adding `storyProgress`, audit all setters that modify progress state.
- **React key for re-initialization** (`docs/solutions/ui-bugs/decorative-avatar-overlap-freeze-reading.md`) — Celebration overlays using `useState` lazy initializers for animations need React keys encoding the trigger dimension (lesson number) to force fresh mounts.

## Key Technical Decisions

- **Earned words are derived, not stored**: A word is "earned" if its designated lesson number is in `completedLessons`. No separate `earnedWords` array — avoids sync risk and follows existing derivation patterns (see origin).
- **Extend ReadingProgress interface in-place**: Add `storyProgress` to the existing `reading` localStorage key rather than new keys. Keeps data co-located and avoids `SCOPED_BASE_KEYS` changes. New fields are optional with defaults for backward compatibility.
- **Big Content Words as a separate data module**: Create `src/data/reading/bigContentWords.ts` mapping lesson numbers to content words and image paths. Keeps lesson data and word data independently maintainable.
- **Story chapters as a separate data module**: Create `src/data/reading/storyChapters.ts` with chapter text, new words per chapter, and page groupings. Extracted from Excel via conversion script.
- **Flat sibling routes**: Add `/reading/collection` and `/reading/story` as sibling routes in `App.tsx` (not nested under `/reading`). Each wraps itself in `ReadingProgressProvider` independently — consistent with existing pattern. Route transitions round-trip through localStorage (unmount saves, mount reads). This is acceptable because the save effect fires synchronously on every state change. Test scenario: advance a story chapter then navigate to `/reading` — progress should reflect the update.
- **First-time detection at call site**: In `handleLessonComplete` (ReadingPage.tsx), check `progress.completedLessons.includes(lessonNumber)` and `getContentWord(lessonNumber)` *before* calling `completeLesson`. The celebration overlay blocks further interaction, so the closure-captured `progress` is guaranteed current. Store the result in component state (`pendingCelebration`). The `completeLesson` function itself remains void — no return value change needed.
- **Image format**: WebP for all generated images. Word images ~200×200px (target ≤20KB each), story panels ~800×600px as single 4-panel composite images (target ≤60KB each). Estimated total: ~2.7MB. Lazy-loaded via `loading="lazy"` attribute. Story panels rendered using 4 `<div>` regions with `object-position` to show each quadrant independently for blur control.
- **CSS blur for panel reveal**: Use `filter: blur(8px) grayscale(100%)` → `filter: none` with a CSS transition. Framer Motion's `animate` handles the transition timing. No canvas needed.

## Open Questions

### Resolved During Planning

- **Earned word storage**: Derived from `completedLessons` — no separate tracking needed.
- **Celebration → next action**: R2 specifies tap anywhere dismisses and advances directly to next lesson. The normal completion screen (with Next Lesson button) is skipped on first-time content-word lessons.
- **Story data pipeline**: Excel → CSV export → TypeScript conversion script (same pattern as lessons).
- **Route structure**: Flat sibling routes, each independently providing their own context.
- **Panel blur technique**: CSS `filter: blur() grayscale()` with Framer Motion transition.
- **New localStorage keys**: None needed — extend existing `reading` key with optional `storyProgress` field.

### Deferred to Implementation

- **Nano Banana 2 prompt tuning**: Exact prompts require experimentation with the API. Unit 1 handles the discovery.
- **Header icon exact positioning**: Depends on visual testing across viewport sizes. Unit 9 handles this.
- **Story chapter tokenization for word-tap**: May need adjusted punctuation rules vs. lessons. Resolved when implementing Unit 3.

- [ ] **Unit 11: Story reader page — core reading flow**

**Goal:** Build the story reading experience at `/reading/story` with chapter text display, page navigation, and reading mode toggle.

**Requirements:** R8, R10, R12, R13

**Dependencies:** Unit 3 (story data), Unit 4 (story progress)

**Files:**
- Create: `src/pages/reading/StoryReader.tsx`
- Create: `src/pages/reading/components/WordHighlightDisplay.tsx` (extracted shared component)
- Create: `src/pages/reading/components/StoryNav.tsx`
- Modify: `src/pages/reading/components/LessonDisplay.tsx` (delegate to WordHighlightDisplay)
- Modify: `src/App.tsx` (add route)

**Approach:**
- **Shared tap-advance component**: Extract the word-highlight state machine (highlightIndex tracking, advance(), keydown/click handlers, token rendering) from `LessonDisplay` into a reusable `WordHighlightDisplay` component. Both `LessonDisplay` and story chapter reading delegate to it. `WordHighlightDisplay` accepts `tokens: WordToken[]`, `onComplete`, and `fontSize` — no lesson-specific semantics. `LessonDisplay` becomes a thin wrapper adding lesson-specific completion UI.
- Layout: side-by-side on screens ≥768px (Tailwind `md:` breakpoint), stacked on mobile. Left/top: 4-panel image area (Unit 12). Right/bottom: chapter text area.
- Chapter text area shows one chapter at a time from the current page's 4 chapters
- **Tap-to-advance mode** (default): tap anywhere in text area advances to the next chapter. Within a chapter, no word-by-word highlighting — the full chapter text appears at once.
- **Word-tap mode**: Uses `WordHighlightDisplay` with `getChapterTokens()` — words highlight one by one, tap advances to next word. After the last word, chapter is marked complete and the next chapter begins.
- **Toggle UI**: Small pill button in the bottom-right corner of the text area, above the page nav. Two states labeled "Read" (tap-to-advance) and "Practice" (word-tap). Mode preference persists in `storyProgress.readingMode`.
- **Chapter/page navigation state machine**:
  - Chapters advance within a page: chapter 1 → 2 → 3 → 4
  - After completing chapter 4, tap-to-advance stops. A "Next Page" button appears. User must tap the button to advance to the next page.
  - Prev/Next page buttons at bottom. Prev disabled on page 1. Next enabled only on pages where all 4 chapters are complete. Prev navigates to the previous page showing all 4 chapters as complete (panels sharp).
  - On re-visiting a previously completed page, all chapters are shown as read.
- On mount: resume from `storyProgress.currentPage` / `storyProgress.currentChapter`. First-time open with no saved position starts at page 1, chapter 1.
- Story completion (page 25, chapter 4 done): congratulatory message + "Read Again" button. "Read Again" resets `currentPage` to 1 and `currentChapter` to 0 but does NOT clear `chaptersRead` (panels stay sharp on revisited pages). Back to `/reading` link also available.
- Wrap in `ReadingProgressProvider`

**Patterns to follow:**
- `LessonDisplay.tsx` for tap-advance and word-highlight state machine (to be extracted)
- `ReadingPage.tsx` for provider wrapping and AnimatePresence transitions
- `LessonNav.tsx` for prev/next navigation buttons

**Test scenarios:**
- Happy path: Open story → resumes at saved position (page 1, chapter 1 for new user)
- Happy path: Tap through 4 chapters → "Next Page" button appears → tap → page 2 loads
- Happy path: Toggle to word-tap mode → words highlight one by one → toggle back to read mode
- Happy path: Navigate prev/next pages
- Edge case: Page 1 → prev button disabled
- Edge case: Tap in text area after chapter 4 completes → nothing happens, must use "Next Page" button
- Edge case: Page 25, chapter 4 completed → congratulatory message, "Read Again" + "Back to Reading" options
- Edge case: "Read Again" → page 1, panels sharp for already-read chapters
- Integration: Progress saves on each chapter advance — closing and reopening resumes correctly
- Integration: Navigate from `/reading/story` to `/reading` and back — progress persists via localStorage round-trip
- Edge case: Direct URL to `/reading/story` when story not unlocked → redirect to `/reading`
- Edge case: `LessonDisplay` still works correctly after extraction into `WordHighlightDisplay` wrapper (no regression)

**Verification:**

- Both reading modes work with correct toggle behavior
- Shared `WordHighlightDisplay` used by both lessons and story
- Progress persists across browser reloads
- Locked-out users cannot access via URL

## System-Wide Impact

- **Interaction graph:** `handleLessonComplete` checks for first-time content-word before calling `completeLesson` → sets `pendingCelebration` state → `ReadingContent` conditionally renders `WordCelebration` or `InlineWordBadge` → celebration dismiss chains to either `handleNextLesson` or `StoryInvitation`. The existing `LessonDisplay` → `onComplete` → `handleLessonComplete` callback chain is preserved. `LessonDisplay` receives `suppressCompletion` prop when a celebration is active.
- **Error propagation:** Image load failures should not block lesson completion or story reading. Use `onError` handlers with placeholder fallbacks on all image-bearing components (WordCelebration, StoryInvitation, StoryPanels, CollectionGallery).
- **State lifecycle risks:** The `storyProgress` field is optional with defaults — no migration needed. The `completeLesson` function signature is unchanged (remains void). User reset clears everything including story progress (same key).
- **API surface parity:** No external APIs affected. The Nano Banana 2 integration is a build-time script, not runtime.
- **Integration coverage:** Test that the celebration → next lesson → celebration chain works correctly when consecutive lessons both have content words (e.g., lessons 79–100 have frequent content words). Test that story progress survives user profile switching.
- **Unchanged invariants:** The existing lesson flow (word tapping, mastery counting, version selection, lesson picker) is not modified. The `readingLessons` data structure is unchanged. The `handleNextLesson` and `handleBack`/`handleForward` navigation functions are unchanged.

## Risks & Dependencies

| Risk | Mitigation |
|------|------------|
| Nano Banana 2 style inconsistency across 86 images | Small-batch test (3 word + 1 panel) before full generation. Iterate prompts until consistent. |
| 86 images add to repo size (budget: ~2.7MB total — words ≤20KB each, panels ≤60KB each) | WebP format at target dimensions. Lazy loading prevents upfront load. Verify per-image sizes after generation; re-optimize if over budget. |
| Save-on-mount race condition in extended context | Follow existing sync init pattern. Code review checkpoint before merge. |
| Celebration overlay on rapid lesson completion | Debounce celebration trigger. React key forces clean remount per lesson. |
| Story mode complexity delays delivery | Phased: ship Part 1 (words + collection) first, Part 2 (story) second. Each is independently valuable. |
